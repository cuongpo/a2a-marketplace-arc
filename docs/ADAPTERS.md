# Real-input path: device and field-operator adapters

The provider agent accepts a signed observation from three sources:

1. `simulated-fixture`: generated by the backend with testnet-only device keys. Always labelled SIMULATED. Disabled on mainnet or with `FQ_ENABLE_FIXTURE=0`.
2. `field-operator-upload`: a field operator signs a reading offline with a device key registered to the winning provider and pastes or uploads the JSON.
3. `device-adapter`: a script that reads a physical gauge and posts the signed reading.

The `kind` for uploads is asserted by the uploader. The system records and displays it but cannot verify that a real instrument produced the number.

## Adapter interface

An adapter produces `{ valueMm, rawPayload, serial }`, signs it, and POSTs `SignedReadingInput` (see `src/shared/types.ts`) to `POST /api/missions/:id/observation`. The POST is authorised by a wallet signature from the provider bound to the mission (not by the device key): request a challenge, sign it, send it in the `Authorization` header (`scripts/lib/signed-api.ts` does this). The device key separately signs the reading inside the body.


```json
{
  "reading": { "missionId": "7", "tileId": "0x...", "observedAt": 1790000000, "value": "412", "unit": "0x...", "nonce": "123456789", "payloadHash": "0x..." },
  "signature": "0x...",
  "rawPayload": { "raw": "412mm" },
  "kind": "device-adapter",
  "deviceSerial": "GAUGE-0042"
}
```

`payloadHash` must equal the keccak256 of the canonical JSON of `rawPayload`. The EIP-712 domain is `FieldQuest EvidenceRegistry` v1 on the chain id and registry address in `src/deployments/*.json`.

## Samples

- `scripts/sign-reading.ts`: offline signer. `DEVICE_KEY=0x... bun run scripts/sign-reading.ts --onchain-id 7 --tile B2 --value 412 --serial GAUGE-0042 --payload '{"raw":"412mm"}'`
- `scripts/ingest-sample.ts`: reads one JSON line (serial or HTTP body) from stdin, signs and posts it.

Register the device key first. The provider calls `EvidenceRegistry.registerSigner(deviceKey, metadataHash, deviceSignature)`; the device signs `SignerBinding(provider, signer, metadataHash)` so nobody can bind a key without its holder's consent.
