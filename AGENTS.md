# A2A Marketplace

> Built with Arc Studio. Project memory for future agents.

## What this app does

An A2A market for signed data requests on Arc. Operator wallets fund a vault, external provider wallets bid with EIP-712 quotes, the buyer agent selects one provider and funds escrow, and the provider submits signed evidence for verification and USDC settlement. Current service category is water-level data. Existing contracts and evidence schemas retain their original `FieldQuest` cryptographic identifiers for compatibility.

## Tech stack

- Frontend: React 18, Vite, TypeScript, Tailwind, wagmi v2, viem, framer-motion (`src/`)
- Backend: Bun (`server/`), persisted state in `data/` (gitignored), run with `bun run server`
- Contracts: Solidity 0.8.28 + Foundry in `contracts/` (tests in `contracts/test/`)
- Shared types/ABIs/typed-data: `src/shared/` (`abis.ts` is generated by `bun run gen:abis` after `forge build`)

## Decisions

- Money: USDC ERC-20 view only, 6 decimals, integer base units. Never mix with the 18-decimal native view.
- Arbiter timeout: the signed verifier verdict stands; no verdict means full buyer refund.
- Vault only trusts escrows fixed at construction (fixes a pooled-vault drain found in review).
- Lint autofix strips `as` casts it thinks are unnecessary; use typed variables instead (see `server/chain.ts`).
- Real public-testnet journeys (setup, 2 accepted, 2 rejected, 1 dispute) completed and verified; mission #5 used the EIP-712-signed API after hardening. All links are in `docs/TESTNET_WALKTHROUGH.md`. Re-verify with `bun run scripts/fq-verify.ts`.
- Public Arc Testnet RPC: use address-only getLogs (see `escrowEvents`), retry with backoff, cache receipts.
- Reliability history shifts agent choice: scripted reject price gap widened so Provider B wins even after A has been paid.

## API auth (hardening)

- All POSTs except `/auth/challenge` need `Authorization: A2AMarket nonce=..., signature=...` (EIP-712 `ApiRequest`, single-use nonce, 120 s, bound to method + path + canonical body hash + chain id). See `server/auth.ts`, `server/authz.ts`, `server/http.ts`.
- Scripts sign with role keys via `scripts/lib/signed-api.ts`. Never POST to the live server as the demo operator unless you intend to spend vault funds.
- The Arc Studio badge in `src/main.tsx` is an in-flow element after the footer, not fixed.
- Browser challenge is a normal wallet tx to `AgentBudgetVault.challengeMission`; arbitration goes through the API only for the arbiter address.
- The trading floor uses user-provided Modern tiles Free sprites. The original license in `public/assets/modern-tiles/LICENSE.txt` permits non-commercial use only. Preserve that notice and use separately licensed art for any commercial release. The React scene is a view of mission and chain state; replay reconstructs only recorded milestones.
- Character idle/run strips have 24 frames in four six-frame groups: right, up, left, down. Stationary agents face down toward the viewer; walking uses the matching heading. The full-width floor has buyer, escrow and verifier plus one avatar per signed provider quote, with two provider avatars visible on compact screens and three on desktop. The selected quote and winner stay visible; the bid strip exposes every quote, score, signature and signer. The scene shows only recorded mission, quote, evidence and chain facts; never invent a payout during replay. Keep objects, labels and bubbles inside both canvas sizes (640x400 desktop, 320x440 compact). The viewport breakpoint at 620px must match the CSS aspect ratio breakpoint.
- Paid second-source verification is opt-in on Arc Testnet. The buyer uses a separate prepaid Circle Gateway wallet to call a separately operated x402 seller. The seller signs a mission-bound reading; the verifier checks that signature, source independence, payment record and agreement. No reference fixture fallback is allowed for `requireSecondSource`. Gateway payment references are not necessarily individual chain transaction hashes. After an interrupted attempt, only an operator-signed retry can trigger another payment.
- Paid reference demo: seller key lives only in `.env.seller` (gitignored; the seller starts with `--no-env-file --env-file=.env.seller`). The backend `.env` holds only the buyer key plus the seller's public address and URL. The reference feed is a SIMULATED fixture (`data/reference-feed.json`, ignored).
- Mission #6 (tile A1) used exactly one paid 0.001 USDC x402 reference.
